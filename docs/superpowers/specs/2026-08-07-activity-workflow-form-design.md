# 活動追加Workflow入力フォーム 設計

## 目的

GitHub Actionsから活動を追加するときの入力ミスを減らし、エディタを開かずに迷わず登録できるようにする。

## 採用方針

GitHub Actionsの`workflow_dispatch`フォームを改善する。GitHubにはカレンダー型の日付入力がないため、日付は自由入力欄を維持するが、具体例を表示し、登録処理側で一般的な表記を正規化する。活動タイプは固定候補が明確なため、`choice`入力に変更する。

## 入力仕様

- `title`: 必須の文字列入力。活動名を入力する。
- `date`: 必須の文字列入力。`2026-08-07`または`2026-08-07〜2026-08-09`を基本例とし、既存の正規化処理で`/`、`~`、日本語表記も受け付ける。
- `type`: 必須の選択入力。既存データで使われている活動種別を候補にし、未分類用に`その他`を含める。
- `venue`: 任意の文字列入力。
- `description`: 任意の文字列入力。
- `url`: 任意のURL入力。

## データフロー

1. GitHubのRun workflow画面で入力する。
2. `add-activity.yml`が入力値を環境変数経由で`bin/add_site_entry.py`へ渡す。
3. 日付と文字列を正規化・検証する。
4. `_data/activities.yml`へ追加し、重複を拒否する。
5. `github-actions[bot]`がデフォルトブランチへcommit・pushする。

## エラー処理

- 不正な日付は、受け付ける形式を示すエラーメッセージで終了する。
- 逆順の日付範囲、重複エントリ、不正なURLは既存どおり拒否する。
- `type`の`その他`は有効な値として保存する。自由な新種別が必要な場合は後から候補を追加する。

## テスト

- 既存の活動追加テストを維持する。
- 一般的な日付表記が正規形式へ変換されることをテストする。
- Workflowが`choice`入力と説明文を持つことをテストする。
- 全Pythonテスト、WorkflowのPrettier検査、差分検査を実行する。

## 非採用案

- 年・月・日を個別の選択欄に分ける案は、期間入力時の操作量が多いため採用しない。
- カレンダー付きの別Webフォームは、認証・GitHub API連携が必要になり、今回の目的に対して実装と保守の負担が大きいため採用しない。
