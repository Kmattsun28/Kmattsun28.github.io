# インタラクティブなトップページ 設計

## 目的

エンジニアのポートフォリオとして、触って面白く人柄が伝わるトップページにする。
同時に、論文・活動を探しに来た人の邪魔をせず、件数が増えてもトップの長さがほぼ一定に保たれるようにする。

参考モックはローカルの`_mocks/10-combined.html`・`10-list.html`（git管理外、`python3 -m http.server`で配信）。
本設計はモックの見た目と振る舞いを本番のJekyll構成へ移すためのもので、モックのコードはそのまま流用しない。

## 採用方針

- トップページ（`/`と`/en/`）を新しいレイアウト`home.liquid`で作り直す。
- サーバー側（Liquid）で全セクションを既定順・既定の3件で描画し、JavaScriptは並べ替え・選び直し・地球儀・質問欄を後から加える（JavaScriptが動かなくても全情報が読める）。
- 表示データはすべて`_data/*.yml`から生成し、手で写したデータは持たない。
- サイト全体の配色を、生成り色の紙と焦げ茶のインクの明るいトーンに統一し、ダークモードは廃止する。

## 画面構成（トップページ）

上から順に次を置く。

1. ヘッダー: 名前、セクションへのナビ、言語切り替え（日本語⇔EN）。時計は置かない。
2. ヒーロー: 英字名、和名（英語版は所属研究室）、所属、研究興味、ポラロイド風の写真。
3. 訪問者の選択: 「どなたですか？」と、研究者／学生・後輩／企業の方／友人／通りすがりのボタン、選んだ理由の一文。
4. セクション（並べ替え対象）: 論文、活動、スキル、足跡（地球儀）、学歴、趣味。
5. 連絡先（常に最後）。
6. フッター: 「このブラウザに残した閲覧の記録を消す」リンク。
7. 右下の「✎ 質問する」ボタンと質問パネル。

各セクション見出しには並び順の番号（§1〜）を付ける。

### 論文・活動（上位3件＋すべて見る）

- 各セクションは3件だけ表示し、その下に選び方の一文（例: 「研究者向けに 24 件から 3 件」「新しい順に 3 件（全 24 件）」）と「すべて見る（N件）→」リンクを出す。
- 訪問者を選んでいない状態とJavaScriptなしの状態では、新しい順の3件を出す。
- `featured: true`の項目は、訪問者の種類に関係なく候補の先頭に置く。
- 3件は日付の新しい順に並べて表示する。

選び方の重みは次のとおり（新しさは0〜1.5点を全員に加える）。

| 訪問者     | 論文                        | 活動                                       |
| ---------- | --------------------------- | ------------------------------------------ |
| 研究者     | 論文誌3、国際会議2.5、国内1 | 国際2.5、受賞2、シンポジウム1.5、国内1.5   |
| 学生・後輩 | 国内2、国際会議1.5、論文誌1 | イベント2、シンポジウム2、受賞1.5、国内1.5 |
| 企業の方   | 国際会議2.5、論文誌2、国内1 | 受賞3、国際2、国内1                        |
| 友人       | 新しさのみ                  | イベント3、受賞1                           |
| 通りすがり | 新しさのみ                  | イベント2.5、受賞1                         |

### セクションの並べ替え

- 訪問者ごとのセクションの重み（下表）に、閲覧の記録による加点を足して、点の高い順に並べる。連絡先は常に最後。

| 訪問者     | 論文 | 活動 | スキル | 足跡 | 学歴 | 趣味 |
| ---------- | ---- | ---- | ------ | ---- | ---- | ---- |
| 未選択     | 2    | 1.8  | 1.3    | 1.2  | 0.8  | 1    |
| 研究者     | 3    | 2    | 1      | 1    | 1.2  | 0.3  |
| 学生・後輩 | 2    | 2.5  | 1.6    | 1    | 2    | 1.5  |
| 企業の方   | 2    | 3    | 3.2    | 1    | 2.5  | 1    |
| 友人       | 0.5  | 1    | 0.4    | 2.5  | 0.5  | 3    |
| 通りすがり | 1    | 1    | 0.9    | 3    | 0.5  | 2    |

- 閲覧の記録による加点は、前回の訪問で各セクションを見ていた時間の割合×1.5点と、質問欄で聞いた話題1回につき0.5点。
- 前回選んだ訪問者の種類は、次の訪問で選ばれた状態から始める。もう一度押すと未選択に戻る。
- 900px未満の幅ではヘッダーのセクションナビを隠す。
- 並べ替えはFLIPアニメーションで動かし、`prefers-reduced-motion`では動かさない。
- 記録の内容は画面に文字で出さない。訪問者の種類を選んだときの一文だけを出す。

### スキル

- 分類（言語／開発／研究の進め方／ツール）ごとにボタンを並べ、使い慣れ度を●の3段階（日常的に使う／使える／触ったことがある）で示す。
- ボタンを押すと、その技術を使った論文・活動を下に一覧表示する。
- 中身は後で本人が`_data/skills.yml`に入れる。空のときはセクションごと出さない。

### 足跡（地球儀）

- d3の正射図法で、紙に線で描いた地球儀を出す。ドラッグで回り、操作されるまではゆっくり自転する。
- ピンは場所ごとに1つにまとめ、活動の件数が多いほど大きくする。
- 場所の一覧（件数つき）とピンは双方向に連動する（ホバーで強調、クリックでその場所へ回転）。
- 選んだ場所の説明には、名古屋からの距離とその場所の活動を最大4件出し、残りは「ほか N 件」にまとめる。
- 活動の項目に「⌖ 東京」のような場所リンクを付け、押すと地球儀へスクロールしてその場所へ回る。一覧ページからは`/?place=<id>#footprints`へ戻る。
- 地図データを読めないときは、場所の一覧だけを表示する。

### 余白の書き込み

- 項目に`note`（英語版は`note_en`）があれば、広い画面では右の余白に手書き風の注釈をホバー・フォーカス時に出し、狭い画面では✎をタップして開く。
- 本番には「（仮）」の文言を持ち込まない。注釈のない項目には何も出さない。

### 質問欄（擬似AI）

- サーバーにもAIにもつながらない、ルールベースの応答。キーワード照合で話題を決め、当てはまらなければサイト内容へのTF-IDF検索、それでもなければメールへの案内を返す。
- 答えに使うのはサイトのデータと、本人が確認した返答の型だけ。モックで作った言い回し（「冬になるとそわそわします」等）は持ち込まない。
- 応答関数は`respond(query) → { text, cards }`の1つにまとめ、将来LLMに差し替えられるようにする（差し替え自体は対象外）。
- 話題は、あいさつ、自己紹介、研究、論文一覧、おすすめの論文（`featured`の論文）、最近の活動、受賞、学歴、所属、連絡先、趣味、スキル、AIの仕組み、お礼。
- 論文・活動・スキル・趣味・学歴・足跡の話題を聞かれたら、そのセクションに並べ替えの加点を入れる。
- 質問の言語（日本語を含むか）で答えの言語を切り替える。パネルに「ルールベースの模擬AIです」と明記する。

### 一覧ページ

- `/publications/`、`/activities/`、新設の`/en/activities/`を同じ見た目にする。
- 年ごとに見出しで区切り、年ごとの件数を出す。
- 種類ボタン（すべて／論文誌／国際会議／国内発表、活動は受賞・国際学会発表など）で絞り込める。JavaScriptなしでは全件を表示する。

## データ

既存項目は変えず、任意項目だけを足す。既存データは任意項目なしでもそのまま表示できること。

| ファイル                    | 追加・新設する項目                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `_data/publications.yml`    | `kind`（`journal`/`intl`/`domestic`）、`featured`、`note`、`note_en`                                                             |
| `_data/activities.yml`      | `place`（`places.yml`のid）、`award`、`title_en`、`type_en`、`description_en`、`featured`、`note`、`note_en`                     |
| `_data/places.yml`（新設）  | `id`、`name_ja`、`name_en`、`lat`、`lng`                                                                                         |
| `_data/skills.yml`（新設）  | `name`、`name_en`、`category`（`lang`/`dev`/`research`/`tool`）、`level`（1〜3）、`uses`（論文・活動タイトルに含まれる語の配列） |
| `_data/profile.yml`（新設） | 学歴・趣味（日英）、趣味ごとの`note`。`about.md`/`about-ja.md`本文から移す                                                       |

- 活動の`type`が「受賞」でなくても、`award: true`なら受賞として扱う（WiP奨励賞は`type: 国内学会発表`のまま`award: true`にする）。
- `places.yml`の初期データは名古屋・豊田・東京と、開催地を本人が確認した場所だけにする。モックの仮の場所（ソウル・ナイロビ・バルセロナ・白馬）は持ち込まない。
- 「Add publication」「Add activity」ワークフローと`bin/add_site_entry.py`に、`kind`（論文、選択式）と`place`・`award`（活動）を任意入力として足す。未入力なら項目を書かない。

## 言語

- `/`（日本語）と`/en/`（英語）は別ページのまま、同じ`home`レイアウトを`page.lang`で切り替える。
- `default.liquid`の`<html lang>`は`page.lang`があればそれを使う。
- 英語版の表示は`*_en`項目を使い、なければ元の値を出す。論文タイトルは原語のまま出す。
- 言語切り替えは対になるページ（`/`⇔`/en/`、`/activities/`⇔`/en/activities/`）へのリンク。

## 閲覧の記録とプライバシー

- 記録は訪問者のブラウザの`localStorage`にだけ保存し、外部へ送らない。
- 保存する内容は、訪問回数、最終訪問時刻、セクションごとの閲覧時間、質問した話題の回数、選んだ訪問者の種類だけ。質問文そのものは保存しない。
- 30分以内の再読み込みや言語切り替えは同じ訪問として数える。
- `localStorage`が使えないときは記録せず、既定の並びで表示する。
- フッターのリンクで記録を消し、再読み込みする。

## エラー処理

- JavaScriptが無効、または読み込みに失敗したとき: サーバー描画の既定表示のまま使える。
- `home-data`のJSONが壊れているとき: 拡張機能を止め、コンソールに1行だけエラーを出す。
- d3・topojsonを読めないとき: 地球儀を出さず場所の一覧だけを出す。
- `place`が`places.yml`にないとき、`uses`が何にも当たらないとき: その場所リンク・成果一覧を出さない。ビルドは止めない。
- 不正な`kind`・`category`・`level`: データ検証テストで落とす。

## テスト

- 単体テスト（`node --test`）: 上位3件の選び方（訪問者別、`featured`優先、件数が3未満）、セクションの並べ替え（記録あり・なし）、擬似AIの話題判定と検索とフォールバック、`_data/*.yml`の値の検証（`kind`・`category`・`level`の範囲、`place`の参照先）。
- Pythonテスト: 追加した任意入力が書き込まれること、未入力なら項目を書かないこと、ワークフローに入力欄があること。
- テストを先に書き、失敗を確認してから実装する。

## エンドツーエンドの確認

1. `docker compose up`でビルドし、`/`、`/en/`、`/publications/`、`/activities/`、`/en/activities/`を開く。
2. 375px幅とPC幅で、横スクロールが出ないこと、コンソールエラーがないことを確認する。
3. 各訪問者ボタンで、セクションの順番と論文・活動の3件が表の重みどおりに変わることを確認する。
4. 活動の場所リンク、一覧ページからの`?place=`での戻り、地球儀のピンと一覧の連動を確認する。
5. 質問欄で「おすすめの論文は？」「趣味は？」「メタバース」「天気は？」を試し、話題判定・検索・フォールバックが出ることを確認する。
6. ブラウザのJavaScriptを無効にして、全セクションと全リンクが読めることを確認する。
7. `prefers-reduced-motion`で、並べ替えと自転と文字送りが止まることを確認する。
8. 一時的にダミーの論文・活動を20件ずつ足したビルドで、トップの長さがほぼ変わらず、一覧ページで年見出しと絞り込みが機能することを確認する（ダミーはコミットしない）。
9. 全リンクを確認し、`npx prettier --check`を変更ファイルに、Pythonテストと`node --test`を実行する。

## 対象外

- 時計（目の時計を含む）、ほかのモック案（ターミナル、触れるヒーロー、実績解除、スキー、RPG）。
- 本物のLLMによる応答と、そのための中継サーバー。
- スキルの中身（本人が後で`skills.yml`に入れる）と、実際の訪問場所の一覧の収集。
- 研究ページ・404ページなど、トップと一覧以外のページの作り直し（配色の変更だけが及ぶ）。
- `_bibliography/papers.bib`の扱いの変更。

## 非採用案

- 論文・活動を全件トップに並べる案は、件数が増えるとトップが長くなり、並べ替えの意味が薄れるため採用しない。
- 衛星写真の地球儀（globe.gl）は、紙とインクのトーンに合わず、読み込みも重いため採用しない。
- 閲覧の記録を「おかえりなさい。3回目のご来訪です」のように文字で出す案は、本人の希望により採用しない。
- 訪問者の現地時刻を出す時計は、本人の判断で採用しない。
